# Steam 上架標準（敘事／章節製作）

> 系列完整規格見 [`guide_line.md`](../../guide_line.md) **§十**。本文件摘錄**故事架構 Agent**須在撰寫、審查章節大綱時對照的條目。  
> 技術上架（Electron、Steamworks、膠囊圖尺寸等）非本 skill 範圍，見 `guide_line.md` §10.5–§10.6。

---

## 1. 類型定位（商店文案須一致）

| 項目 | 規格 |
|------|------|
| **主類型** | Story Rich 敘事；**電子書式閱讀節奏** + 輕互動 |
| **互動** | 選項分支、小遊戲、撫摸、相簿／日記 |
| **不是** | 純 kinetic novel、寵物經營 sim、全程催淚 sim |
| **結構** | 三部曲可單章購買；跨作存檔延續記憶 |

**建議標籤（敘事相關）：** Emotional、Story Rich、Choices Matter、Singleplayer、Dogs、Indie；（次要）Life Sim、Visual Novel

**基調（文案勿誤導）：** Ch1 暖有笑 → Ch2 靜日常 → Ch3 克制告別。

---

## 2. 內容量與時長（章節大綱必達）

| 層級 | 目標 | 敘事 Agent 責任 |
|------|------|-----------------|
| **付費單章主線** | **>2 小時**（退款安全線） | 全章總覽表時長加總須達標 |
| **付費單章** | **3–5h** 主線；**4–6h** 全收集 | 規劃場景數與分支密度 |
| **三部曲主線** | **9–15h** | 不為湊時長灌水；以 Landmark／分支質量為準 |

### 單章製作估算

| 指標 | 單章目標 |
|------|----------|
| **場景節點** | ~90–110（含分支）；一節點 ≈ 一個 `scene_id` |
| **中文字數（粗估）** | 6–12 萬字（含分支、`sub`） |
| **Landmark** | ≥3；觸發後鎖定、寫入跨作存檔 |
| **收束結局** | ≥3 條 + 可重玩壞結局章（無 permadeath） |
| **笑暖** | 每週 ≥1 笑 + ≥1 暖（Ch1 見章節指南笑暖排程） |

## 3. 全章總覽表（每章指南必備）

撰寫或審查章節大綱時，須維護**固定欄位**的總覽表（置於 `Ch?_*/Ch?_guide_line.md`）：

| 段落 | 故事日 | 主題句 | 場景數（目標） | 預估時長 | 必達 Memory／Landmark | 笑暖／條件 | Bond |
|------|--------|--------|----------------|----------|----------------------|------------|------|
| （依章填寫） | | | | | | | |
| **合計** | | 篇章主題一句 | **~90–110** | **主線 3–5h** | 結局路線數 | 每週笑暖 | Lv 里程碑 |

**審查規則：**

1. 各段落場景數加總 ≈ 合計列（±10% 內說明分支緩衝）。
2. 各段落時長加總 ≈ 主線 3–4h（全收集可至 4–6h）。
3. 每段落至少 1 個必達 Memory 或 Landmark（笑暖 Moment 可並列）。
4. Bond 里程碑與 `guide_line.md` §6.3 五階一致。

見 [`Ch1_Trust/Ch1_guide_line.md`](../../Ch1_Trust/Ch1_guide_line.md) §全章總覽表：

| 段落 | 場景數 | 預估時長 | Bond |
|------|--------|----------|------|
| 第一週 1–7 | ~53–58 | ~45–50 min | → Lv2 |
| 第二週 8–14 | ~12–15 | ~45–60 min | — |
| 第三週 15–21 | ~14–16 | ~60 min | — |
| 第四週 22–28 | ~10–12 | ~45 min | → Lv3 |
| 週年弧 365 | ~6–8 | ~30–45 min | Ch1 終局 |
| **合計** | **~95–105** | **主線 3–4h／全收集 4–5h** | Lv1→Lv3 |

## 4. 敘事結構與商店承諾

撰寫章節大綱、結局、分支時，須能支撐商店長描述中的承諾：

| 承諾 | 敘事要求 |
|------|----------|
| **選擇有重量** | Landmark 鎖定；重大選擇寫入 `flags`／跨作存檔 |
| **多條收束** | 每章 ≥3 條終局路線（條件表 + 結尾一句） |
| **壞結局可重玩** | 短 epilogue + 可重玩該週；不清零全系列 |
| **個人化記憶** | 相簿 Memory 覆蓋主線關鍵節點；第三部可閃回 |
| **基調誠實** | Ch1 不賣死亡；Ch3 才寫告別；Ch2 敏感主題見內容警告 |

### 商店文案草案（敘事 Agent 可產出）

**短描述要素：** 一句話賣點 + 選擇／記憶機制 + 單章預估時長（勿夸大）。

**長描述要素：** 三部曲結構、**本章**時間跨度、主題、互動類型、結局種類、內容警告（若適用）。

草案見 `guide_line.md` §七 Steam 短描述。

## 6. 敘事 Agent 工作流程（Steam 對齊）

### 新章／擴章大綱

1. 讀 `guide_line.md` §十 + 本章 `Ch?_guide_line.md`。
2. 依 §3 模板起草**全章總覽表**（先段落級，再拆逐場景）。
3. 確認 Landmark ≥3、結局 ≥3、笑暖排程、Bond 里程碑。
4. 估算場景數／時長；主線合計 **>2h**、目標 **3–5h**。
5. 產出逐週或逐日大綱 → 場景包。

### 審查既有大綱

- [ ] 全章總覽表欄位完整？
- [ ] 場景數／時長加總合理？
- [ ] Landmark 是否鎖定、寫入跨作？
- [ ] 結局數與條件表一致？
- [ ] 每週笑暖是否到位？
- [ ] 基調是否符合該章（勿 Ch1 催淚、勿 Ch3 搞笑過頭）？
- [ ] 敏感主題是否列內容警告？
